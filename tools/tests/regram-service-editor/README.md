Run `python3 tools/tests/regram-service-editor/run.py` after building RegramCore Release and SwiftSignalKit for the current architecture. Pass `--products` for another directory containing their objects and Swift modules. The runner uses one small swiftc invocation and does not build a package.

The fixture compiles the production RegramServiceController and keeps its ServiceDraft, update/persistence, action closures, request cancellation and generation checks intact. It reuses the frozen network editor's action-independent row-reuse fixture without editing that directory. LLM configuration and URL assembly, STT configuration validation, transcription errors, RegramCore preferences and SwiftSignalKit are production code.

Credential reads/writes use an in-memory replacement. Providers return controllable real Signals and never create HTTP requests. The STT sample resource lookup alone is redirected to a memory:// URL accepted by its provider substitute; no audio is read. UI rows, alerts and navigation context are substitutes. Preference persistence uses a unique suite removed afterward.

Coverage retains old test/fetch actions while editing base URL, model and API key; verifies the current configuration and memory credential; checks old model-list removal after base URL, key and format changes; and exercises both late success and late failure after model/base/key/format edits, with a new request active. It also checks STT cancellation through an old action, key-edit cancellation, leaving the page and LLM controller deinitialization. Real Signal disposal and the production generation guards are tested together; the fixture does not bypass a disposed Subscriber to invoke private callbacks directly. No real Keychain, account, file, window or paid service is used.

The credential retry cases inject two failed memory writes, retain the original test or model-fetch action, then allow the retry to succeed. They verify that only the successful retry advances the service identity, the provider receives the saved key, and subsequent tests do not repeatedly advance it. `--controller-source` accepts a saved production controller for a negative control.
