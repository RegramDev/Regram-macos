# 2026-11-01 音乐加载、分页与变更状态修复

上游合并后记录的音乐加载 38 个失败用例已修复。原有 47 个用例保留断言，新增 4 个边界用例后，完整音乐套件共 51 项通过，零失败。

## 根因与修复

`ProfileSavedMusicContext` 原先没有处理请求失败或无数据完成，加载状态无法收束；重新加载会先清空已有歌曲。现在失败、空完成和缺失用户均恢复为可重试状态，重载期间保留已有内容，晚到的有效缓存也可显示。

分页偏移原先使用可见歌曲数量，重复或无法解析的文档会使下一页偏移重复。现在按服务器原始文档数量推进独立游标，按完整 MediaId 合并歌曲并刷新重复条目的元数据。失败重试沿用原始偏移，空原始页结束分页，hash 为零时意外返回 NotModified 不再清空歌曲。

请求和缓存读取使用版本身份及订阅前安装的子持有者，避免状态观察者同步触发重载后，外层请求覆盖新请求。缓存写入独立持有，加载后续页不会取消第一页待完成的写入；重载、增删和销毁会使旧写入版本失效。事务主体本身也校验写入版本，已经可执行的旧数据库回调不能覆盖新结果。

增删操作原先在创建信号时就改动可见列表，并在服务器确认前写入缓存；并发修改没有阻止旧分页回填。现在普通增删在订阅后才应用可见列表变化，撤销旧页面和缓存工作，并等全部已订阅修改结束后从第一页刷新。同步嵌套操作按调用顺序启动请求；取消的排队操作不会补发；错误、完成和取消只释放一次持有状态。`apply: false` 保留其立即本地更新、不发送请求的约定。

原始增删接口仅在服务器返回 true 后更新账号歌曲缓存、已知歌曲 ID 和资料音乐。服务器拒绝或失败时保留这些数据，添加失败继续向调用方报告错误。上下文和缓存使用同一排序方法；移到自己之后不发请求，重复删除不再反复减计数，移走或删除首曲时更新资料音乐。通过他人资料保存或移除歌曲只修改自己的音乐库，不改写他人的可见列表。
