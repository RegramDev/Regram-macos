# 长时间运行后负载升高的代码复查

用户反馈高负载和长时间运行时，分组、对话切换变慢，要求继续从代码层面检查后台任务积压。本轮没有自动切换用户账号的聊天或分组，也没有对运行中的账号做性能采样。

## 确认并修正的路径

| 路径 | 原行为 | 修正 |
| --- | --- | --- |
| 对话历史订阅的强引用环 | 控制器持有 historyDisposable，mapToQueue 闭包为写入 currentRanks 又强持有控制器；移出导航栈本身不能解除这条引用链。 | 渲染闭包弱引用控制器，管理员等级回写使用可选访问。保留正常渲染与权限数据更新，避免订阅延长控制器生命周期。 |
| 离开导航页面的对话历史 | 控制器仍被导航栈持有时，消息历史、主题、翻译和其他展示状态更新继续触发条目转换与布局。原有 visibility 值没有参与这条计算管线。 | 在历史输入排入渲染队列前检查页面可见性；隐藏时保留最新原始快照。页面返回时恢复处理。排队更新携带可见性世代，在重计算前排除旧世代。 |
| 滚动后的延迟消息任务 | heavyScrollWorkItem 仅在清理或销毁时取消，切换页面后仍可能触发消息计数、媒体、反应和翻译等可见消息处理。快速返回页面时，单纯在执行时检查可见性仍可能让旧任务通过。 | 隐藏、失去窗口焦点和清理时取消工作，安排及执行时都检查可见页面状态；重新显示后按当前可见消息重新安排。 |
| 聊天列表 Story 资源 | 列表离开屏幕后，Story 订阅和媒体资源预加载继续存在。 | 订阅同时受列表 viewOnStage 和隐藏 Story 偏好控制。列表隐藏时解除订阅并交付空资源集，取消已有媒体预加载；主线程交付放在可取消的内层信号中，防止旧结果恢复已取消资源。 |
| 过滤消息预览的远端续页 | 已取消请求的 50 毫秒定时续页仍可能发起请求；同一来源键被重新请求时，旧任务可能结束并取消新请求。 | 请求启动和结果回调都验证页面仍活跃、来源键相同，并且 MetaDisposable 与当前请求实例相同。旧续页定时器到期后直接退出。 |

历史仍使用控制器原有串行队列。前台消息更新保留原顺序；初始准备默认启用，避免聊天导航等首屏就绪形成循环等待。后台任务修正没有重订阅消息历史或改写账号同步。用户本轮补充的机器人防撤回开关另见 [机器人消息开关记录](regram-revoked-bots-20261029.md)，该功能需要调整核心删除入口的判断。

另核对导航 push 的 ready 订阅：它会强持有等待就绪的目标控制器，加入栈后由导航栈持有；取消等待则释放该订阅。因此历史渲染改为弱引用不需要依赖自持有来维持首屏准备。

历史渲染暂停只跟随页面离开和返回，不跟随窗口焦点。未聚焦但仍可见的窗口继续接收消息刷新；失去焦点时只取消滚动后的延迟可见消息工作。

## 回归证据

- 新增生命周期隔离回归 16 项，以真实 SwiftSignalKit 在 Release/STABLE 运行，全部通过。覆盖 5,000 次隐藏历史更新、1,000 次过期排队更新、隐藏页面状态更新、Story 取消与主线程竞态、远端续页请求替代、延迟滚动取消和历史订阅所有者释放。
- 释放测试从生产渲染闭包提取捕获方式及 currentRanks 回写，在受控所有者中重现相同持有关系。修复前对象未释放、订阅未取消、后续消息仍交付，触发 3 个断言；修复后对象释放并取消订阅。这不是完整 AppKit 控制器的内存测量。
- 临时源码恢复旧策略后，11 项指定反例全部按预期失败，共触发 19 个断言。此结果来自受控队列和合成消息，不是完整旧版应用的运行测量。
- 现有过滤聊天列表一致性检查 176 项通过。修正了脚本中上一轮分页快照已移到主线程应用后留下的旧接入断言，没有调整生产分类规则。
- 首屏和滚动的既有 Release/STABLE 回归 20 项通过，日志为 `/tmp/regram-long-running-chat-opening-20261029.log`。

测试源码、提取边界和运行方式见 [regram-long-running 回归说明](../tools/tests/regram-long-running/README.md)。主要日志：`/tmp/regram-long-running-20261029/tests.log`、`/tmp/regram-long-running-before-20261029/tests.log`、`/tmp/regram-long-run-filter-parity-20261029.log`。

## 其他检查与结论边界

AccountContext 的时间差刷新和主题刷新属于既有周期同步；没有发现无间隔重试。检查 SwiftSignalKit 后确认，已完成订阅会释放内部资源，DisposableSet 仍持有包装对象不能直接认定为活跃后台任务。导航栈已有旧根对话清理，但这不足以解除渲染订阅的强引用环，所以本轮另行修正了上述闭包捕获。账号周期同步和导航栈清理规则保持原行为。

这轮修正了可从代码和隔离回归确认的多余工作与取消漏洞。尚未捕获用户真实账号长时间运行后的异常高负载，因此不能认定这些路径解释了全部卡顿，或声称长期运行的 CPU 峰值已完全消失。
