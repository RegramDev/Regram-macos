# 分组、对话切换与链接悬浮预览

## 用户现象

- 分组和对话切换偶发响应慢，高负载、长时间运行时更容易出现；同一时刻切换设置界面通常没有明显延迟。
- 悬停链接显示包含名称和头像的预览，鼠标移开后仍留在原处。
- 按用户后续要求，修正以代码路径和隔离回归为主，不继续自动操作其聊天界面。

## 代码修正

聊天列表原先在全局 `PrepareQueue` 上生成条目和过滤预览。该队列为 utility 优先级，还承载其他资源准备；前台切换必须等待已经排入该队列的工作。现在每个聊天列表持有自己的 userInitiated 串行队列，列表管线和预览协调器共用该实例。所有协调器状态、订阅结果和清理继续串行处理；资源预加载保留原有后台队列。

对话导航原先直接订阅异步 peer 查询，没有取消上一次查询。现在按导航容器保存请求代次，新请求取消旧查询和未完成的 push。过期查询、重入后晚安装的订阅及已经离开原控制器的响应不能打开旧对话。取消待加载控制器会释放其持有关系，使控制器能够及时清理后台工作。

链接预览原先使用点击菜单模式，悬浮取消只取消查询，没有关闭已经显示的弹层。现在预览按 hover 模式呈现，独立生命周期对象负责查询和所属菜单；鼠标离开、源视图取消、窗口失活及关闭预览的清理能够衔接。迟到响应不能重新打开已取消的预览，关闭时只关闭自己的弹层。

## 验证与边界

- 23 项原生生命周期与菜单 XCTest 通过，使用 Release/STABLE。
- 恢复旧共享队列的负对照按预期令两项前台处理检查失败；独立队列版本通过。
- 176 项过滤列表策略、协调器和缓存检查通过，队列改造后没有改变过滤、分页和已读提交规则。
- 91 项分组路由、模型复用、归档与原生头部布局检查通过。
- 初始 30 秒 Release 线程采样主要表现为空闲等待，未捕获用户描述的偶发长时间卡顿。样本及匹配 UUID 的符号化结果位于 `/tmp/regram-switch-latency-20261029/`，不作为修复前后的真实延迟基准。
- 这些修正消除了代码中确认的排队及过期工作路径；没有宣称已经自动复现并验证所有长期、高负载场景。
